명령어 사이클과 인터럽트

CPU는 명령어를 인출하고 해석해 실행하며, 필요하면 메모리에 접근하고 결과를 기록한다. 인터럽트가 승인되면 정상 실행 흐름을 전환해 장치의 요청을 처리한다. RISC-V CSR과 MicroBlaze V의 외부 인터럽트 연결을 함께 살펴본다.

명령어 사이클 — 다섯 단계의 반복

6장 · 2 / 10

CPU가 명령어 하나를 처리하는 과정을 명령어 사이클(instruction cycle)이라 한다. CPU 동작을 이해하기 위한 대표적인 교육용 모델은 IF·ID·EX·MEM·WB의 다섯 단계로 나눈다. 실제 MicroBlaze V의 파이프라인 단계 수는 IP 구성에 따라 달라지고 여러 명령어의 처리가 겹칠 수 있다. PC 갱신 시점도 반드시 WB 단계의 끝은 아니다.

ID 해석opcode를 보고 제어 신호를 만든다, 레지스터를 읽는다제어장치, 레지스터 파일, 즉시값 생성
EX 실행계산하거나 주소를 만들거나 비교한다ALU

인출과 해석 — 무엇을 할지 알아내기

6장 · 3 / 10

처음 두 단계는 모든 명령어가 똑같이 거친다. 인출(IF)에서 PC가 가리키는 주소의 명령어를 가져온다. 32비트 기본 명령어라면 순차 실행 주소는 PC + 4이며, C 확장의 16비트 압축 명령어라면 PC + 2다. 해석(ID)에서는 opcode · funct3 · funct7로 명령어 종류를 알아내고, rs1 · rs2 레지스터를 읽고, 즉시값을 32비트로 늘려 둔다.

예: PC = 0x0000_0000에서 lui a0, 0x40000을 처리할 때
단계일어나는 일값
IFBRAM 주소 0~3을 읽는다37 05 00 40 → 0x4000_0537
IF다음 PC 후보 계산0x0000_0004
IDopcode 0110111 → LUI, rd = 10(a0)레지스터 읽기 없음
ID즉시값 생성: 상위 20비트에 놓고 아래 12비트는 00x4000_0000
부호 확장12비트 즉시값 0xFFF은 −1이다. 32비트로 늘릴 때 맨 앞 비트(1)를 위쪽에 채워 0xFFFF_FFFF로 만든다(2장 2의 보수).
16비트 명령어C 확장 명령어는 16비트 인코딩을 해석해 그에 대응하는 연산을 수행한다. 내부적으로 32비트 형식으로 확장하는지는 CPU 구현에 따라 다르며, 순차 실행 PC는 +2가 된다.
인출할 수 없으면명령어 주소 정렬 오류(압축 확장 사용 여부에 따라 기준이 다름), 접근 오류, 잘못된 명령어 등에서는 예외(exception)가 발생할 수 있다. 일반 트랩 모드에서는 mtvec의 처리 코드로 진입한다.

실행 · 메모리 · 쓰기 — 명령어마다 다르게

6장 · 4 / 10

뒤의 세 단계는 명령어 종류에 따라 하는 일이 다르고, 필요 없는 단계는 그냥 지나간다. 예를 들어 add는 메모리에 갈 일이 없고, sw는 레지스터에 쓸 결과가 없다.

SoC 연결주변장치 레지스터 접근(REG32())은 MEM 단계에서 일어난다. BRAM과 AXI 주변장치의 응답 지연은 실제 IP 구성·클록·버스 상태에 따라 다르다. AXI 응답이 지연되면 명령어 완료가 지연되거나 파이프라인이 정지할 수 있다. 실제 지연 클록 수는 타이밍·성능 측정으로 확인한다.

클록과 사이클 — 시간으로 보기

6장 · 5 / 10

동기식 레지스터는 설계에서 지정한 활성 클록 에지에 상태를 저장한다. 100 MHz로 구동한다고 가정하면 한 클록은 10 ns다. 그림처럼 단계를 겹치지 않고 한 단계에 한 클록씩 할당한 교육용 CPU라면 다섯 클록(50 ns)이 걸린다. 명령어당 평균 소요 클록 수는 CPI(Cycles Per Instruction, 명령어당 클록 수)라 한다.

다중 사이클 (위 그림)10 ns (예시)예시: 5그림에서는 50 ns
파이프라인 (7장)10 ns (예시)이상적으로 약 1처리량은 높지만 개별 지연은 여러 클록
핵심프로그램 실행 시간은 대체로 명령어 수 × 평균 CPI × 클록 주기로 계산한다. 파이프라인은 명령어의 완료 간격(처리량)을 개선하지만, 개별 명령어가 꼭 한 클록에 완료되는 것은 아니다.

폴링과 인터럽트

6장 · 6 / 10

버튼이 눌렸는지 알아내는 방법은 두 가지다. CPU가 상태 레지스터를 계속 읽어 보는 폴링(polling), 그리고 장치가 신호선으로 CPU에 알려 주는 인터럽트(interrupt)다. 인터럽트를 쓰면 CPU는 다른 일을 실행하다가, 허용된 요청을 정해진 경계에서 받아 처리 함수로 진입한다. 폴링도 검사 간격을 두고 다른 작업과 병행하도록 구현할 수 있다.

폴링인터럽트
알아내는 쪽CPU가 주기적으로 확인장치가 신호로 알림
CPU 시간검사 주기·방법만큼 사용진입·복귀 및 처리에 시간 사용
반응 시간확인 간격에 따라 늦을 수 있다우선순위·마스킹·처리 지연에 좌우
만들기쉽다CSR · 처리 함수 · 클리어 순서가 필요하다
우리 실습UART·타이머 상태 검사 예타이머·버튼 인터럽트 예
인터럽트외부 장치의 요청 신호는 명령어 실행과 무관하게 발생할 수 있다. CPU는 허용 비트 및 인터럽트 조건을 확인해 트랩을 받아들인다.
예외명령어 실행 중에 생긴 문제(없는 명령어, 정렬 오류 등). 그 명령어가 원인이다.
트랩(trap)인터럽트와 예외를 함께 부르는 말. 일반 M-mode 직접 트랩에서는 mtvec을 통해 진입하고 mcause로 원인을 구분한다.

인터럽트 처리 순서

6장 · 7 / 10

일반 외부 인터럽트가 허용되면 MicroBlaze V는 실행 단계의 명령어를 완료한 뒤, 다음에 실행할 명령어의 주소를 보존하고 트랩 처리 코드로 분기한다. 이 일부는 하드웨어가 자동으로 하고, 나머지(레지스터 저장, 원인 확인)는 처리 함수(소프트웨어)가 한다. 처리가 끝나면 mret 명령어 하나로 원래 자리로 돌아간다.

순서누가하는 일
① 도착INTC → CPUInterrupt 신호가 올라간다. MIE · MEIE가 켜져 있으면 받아들인다
② 진입하드웨어mepc · mcause 기록, MIE를 0으로 하여 일반 M-mode 인터럽트 중첩을 막고, PC를 mtvec.BASE로
③ 처리소프트웨어쓸 레지스터를 스택에 저장 → 원인 장치를 찾아 처리하고 클리어 → 복원
④ 복귀mret 명령어PC ← mepc, MIE ← MPIE (복귀 처리 완료 후 MPIE도 갱신). 미실행 명령어 D부터 재개
주의레벨 감지 인터럽트에서 원인 장치의 요청이 해제되지 않으면 mret 뒤 재진입할 수 있다. 에지 감지 방식과 ACK 동작은 MicroBlaze V의 C_INTERRUPT_IS_EDGE 및 INTC 설정에 따라 확인한다.

인터럽트 CSR — 설정과 기록

6장 · 8 / 10

인터럽트 설정과 기록은 CSR(Control and Status Register, 제어 상태 레지스터)이라는 특별한 레지스터에 있다. x0~x31과 별개이며 소프트웨어는 csrr · csrw · csrs · csrc 같은 CSR 명령어로 접근한다. 트랩 진입·복귀 때는 하드웨어가 관련 비트를 자동으로 갱신한다. MicroBlaze V는 표준 RISC-V Machine 모드 CSR을 쓴다.

CSR뜻우리가 쓰는 것
mstatusCPU 상태. MIE = 전역 인터럽트 허용, MPIE = 진입 전 MIE 값MIE(비트 3)를 1로
mie종류별 허용: MEIE 외부 · MTIE 타이머 · MSIE 소프트웨어MEIE(비트 11)를 1로
mtvec일반 트랩 진입 주소. MicroBlaze V는 MODE가 읽기 전용 0(Direct)BASE에 4바이트 정렬 주소 등록
mepc복귀 주소. 트랩 진입 때 하드웨어가 기록보통 읽기(필요 시 소프트웨어 쓰기 가능)
mcauseRV32 원인 코드. 비트 31이 인터럽트 구분, 코드 11은 M-mode 외부 인터럽트보통 읽기(필요 시 소프트웨어 쓰기 가능)
SoC 연결일반 외부 인터럽트 경로에서 AXI INTC의 출력이 MicroBlaze V의 Interrupt 포트에 연결되면, M-mode 외부 인터럽트의 mcause는 0x8000_000B가 된다. 예외·다른 인터럽트 원인은 다른 값이며, 어느 주변장치인지 INTC 상태 레지스터로 판별한다.

INTC와 함께 쓰기 — 장치에서 CPU까지

6장 · 9 / 10

MicroBlaze V의 일반 외부 인터럽트 입력 Interrupt는 하나다. 여러 장치의 요청을 쓸 경우 AXI INTC(인터럽트 제어기)로 모아 연결할 수 있다. INTC는 어떤 입력이 왔는지 기록해 두므로, 처리 함수는 INTC의 대기 레지스터(IPR)를 읽어 원인 장치를 찾는다.

INTC 레지스터오프셋뜻
ISR0x00들어온 인터럽트 (Interrupt Status Register — 처리 함수를 뜻하는 ISR과 다른 말)
IPR0x04대기 중 = ISR & IER
IER0x08입력별 허용
IAR0x0C쓴 비트를 ISR에서 지움
MER0x1CINTC 전체 허용(대표적으로 ME 비트 0)

처리 함수의 구조 (주소·비트 정의는 별도 헤더 및 Vivado 연결에 따름)

static void handle_interrupt(void)
{
    uint32_t pending = INTC_IPR;             /* 대기 중인 인터럽트 = ISR & IER */

    if (pending & (1u << INTC_BIT_TIMER)) {
        timer_ack();                         /* 1) 소스(Timer)에서 먼저 클리어 */
        timer_tick_count++;
        INTC_IAR = (1u << INTC_BIT_TIMER);   /* 2) 컨트롤러 쪽도 클리어 */
    }
    /* 다른 입력도 실제 연결과 감지 방식에 맞춰 별도 처리 */
}
핵심레벨 인터럽트에서는 보통 소스 장치의 요청을 먼저 해제하고 INTC에서 ACK한다. 단, 에지 감지·자동 해제 여부와 각 IP의 레지스터 동작을 확인해야 한다. INTC 자체의 IER·MER 설정도 별도로 필요하다.

처리 함수 · 6장 정리

6장 · 10 / 10

다음은 RISC-V M-mode 외부 인터럽트 처리의 교육용 C 예제다. interrupt("machine") 속성이 트랩 처리에 필요한 저장·복원 코드와 mret을 생성한다. 실제 구현에서는 mcause를 구분하고, INTC·소스 장치 초기화 및 인터럽트 확인/해제 코드를 결합한다.

cpu_irq_mbv.c (개념 예제 · 실제 프로젝트 전체본 아님)

#include <stdint.h>
#include "cpu_irq.h"

#define CSR_MSTATUS_MIE   (1u << 3)   /* M-mode 전체 인터럽트 허용 */
#define CSR_MIE_MEIE      (1u << 11)  /* M-mode 외부 인터럽트 허용 */
#define MCAUSE_M_EXT      0x8000000Bu /* RV32 M-mode 외부 인터럽트 */

static void (*s_isr)(void) = 0;

/* GCC RISC-V의 interrupt 속성이 레지스터 저장·복원과 mret을 자동 생성한다.
   mtvec은 4바이트 정렬이어야 하므로 함수도 4바이트 정렬로 고정한다. */
static void trap_handler(void) __attribute__((interrupt("machine"), aligned(4)));

static void trap_handler(void)
{
    uint32_t cause;
    __asm__ volatile ("csrr %0, mcause" : "=r" (cause));

    // (추가) 예외와 외부 인터럽트를 구분한다.
    if (cause != MCAUSE_M_EXT) {
        // 예상하지 못한 예외에서는 같은 명령어로 무한 복귀하지 않는다.
        for (;;) { __asm__ volatile ("nop"); }
    }

    if (s_isr) s_isr();    /* 외부 인터럽트 원인 확인·해제 콜백 */
}

void cpu_irq_register(void (*handler)(void))
{
    s_isr = handler;
}

void cpu_irq_enable(void)
{
    uintptr_t vec = (uintptr_t)trap_handler;

    __asm__ volatile ("csrw mtvec, %0" :: "r" (vec));               /* 트랩 벡터 등록 */
    __asm__ volatile ("csrs mie, %0"   :: "r" (CSR_MIE_MEIE));      /* 외부 인터럽트 허용 */
    __asm__ volatile ("csrs mstatus, %0" :: "r" (CSR_MSTATUS_MIE)); /* 전역 허용 */
    /* 장치·AXI INTC의 IER/MER 및 ACK 설정은 별도로 필요 */
}

trap_handler 어셈블리 주요 구간 (Clang 17 · RV32IMC + Zicsr · -O2)

    addi sp, sp, -64      # 스택 64바이트 확보
    sw   ra, 60(sp)       # ra 등 caller-saved 레지스터 저장
