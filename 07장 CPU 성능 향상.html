파이프라인 — 명령어를 겹쳐 실행

7장 · 3 / 10

세탁기 · 건조기 · 다림질을 차례로 하는 일이라면, 첫 빨래가 건조기에 들어간 동안 두 번째 빨래를 세탁기에 넣을 수 있다. 파이프라인(pipeline)도 같다. 교육용 5단 모델에서는 단계마다 필요한 자원을 적절히 분리하여, 명령어 1이 ID 단계에 있는 동안 명령어 2를 IF 할 수 있다. 실제 MicroBlaze V의 단계 구성은 선택한 최적화 설정에 따라 다르다.

클록마다 끝나는 명령어 수 (처리량)0.2개최대 1개
명령어 5개25클록9클록

핵심파이프라인의 주된 목적은 명령어 하나의 지연 시간 단축이 아니라, 여러 명령어를 겹쳐 실행해 처리량을 높이는 것이다. 단계 분할에 따라 클록 주기도 달라질 수 있다. 이처럼 명령어 여러 개를 겹쳐 처리하는 것을 명령어 수준 병렬성(ILP)이라 한다.

파이프라인 레지스터 — 단계 사이의 칸막이

7장 · 4 / 10

여러 명령어가 동시에 서로 다른 단계에 있으려면, 각 단계가 자기 명령어의 정보를 따로 들고 있어야 한다. 그래서 단계 사이마다 파이프라인 레지스터를 둔다. 정상 진행할 때 클록 경계에서 각 단계의 결과를 다음 레지스터에 저장한다. 해저드가 있으면 일부 단계가 멈추거나 잘못 인출한 명령어를 무효화한다.

데이터 해저드 — 결과가 준비되기 전의 사용

7장 · 5 / 10

겹쳐 실행하다 보면 뒤 명령어가 앞 명령어의 결과를 필요로 할 때가 있다. 앞 명령어의 결과가 아직 준비되지 않았는데 뒤 명령어가 이를 사용하면 데이터 의존성이 생긴다. 전달 회로나 정지 처리가 없다면 이전 값을 사용할 수 있다. 이처럼 파이프라인이 그대로 진행할 수 없는 상황을 해저드(hazard)라 하고, 값 때문에 생기는 것을 데이터 해저드라 한다.

제어 해저드 · 구조 해저드

7장 · 6 / 10

그림의 교육용 5단 모델은 분기 여부를 EX 단계에서 결정한다고 가정한다. 그동안 파이프라인은 이미 다음 명령어들을 인출해 버렸다. 분기하면 이 명령어들을 버려야(flush) 하므로 그만큼 클록이 낭비된다. 이것이 제어 해저드다. 실제 MicroBlaze V에는 선택형 분기 목표 캐시(BTC)가 있어 올바른 예측 시 손실을 줄일 수 있다.

더 많은 병렬성 — 슈퍼스칼라와 멀티코어

7장 · 7 / 10

단일 발행(single-issue) 파이프라인은 이상적인 조건에서 클록당 최대 명령어 1개를 완료하므로 CPI는 1에 가까워진다. 단일 코어의 처리량을 더 높이는 방법에는 한 클록에 명령어 여러 개를 발행하는 슈퍼스칼라(superscalar), 순서를 바꿔 실행할 수 있는 명령어를 먼저 처리하는 비순차 실행(out-of-order), 아예 CPU를 여러 개 두어 독립적인 작업을 병렬 처리하는 멀티코어(multicore)가 있다. 멀티코어는 단일 코어의 CPI를 줄인다는 뜻이 아니다.

방식병렬의 단위누가 병렬을 찾나쓰이는 곳
파이프라인명령어의 단계하드웨어거의 모든 CPU (MicroBlaze V 포함)

비순차 실행기다리는 명령어를 건너뜀하드웨어고성능 CPU
멀티코어서로 다른 작업·스레드운영체제·응용 소프트웨어Apple M1 (8 CPU 코어), 멀티코어 SoC 설계
핵심고성능 기법은 회로를 크게 늘린다. FPGA 안의 소프트 CPU는 남은 자원을 주변장치에도 써야 하므로, 단순한 파이프라인 하나를 두고 필요한 일은 전용 하드웨어(사용자 IP)로 넘기는 경우가 많다.

CISC와 RISC — 명령어 집합의 두 철학

7장 · 8 / 10

CISC(Complex Instruction Set Computer) 계열인 x86은 메모리 피연산자를 직접 사용하는 복합 명령어와 가변 길이 인코딩을 제공한다. RISC(Reduced Instruction Set Computer) 계열인 RISC-V는 정수 연산을 레지스터 중심으로 실행하고, 메모리 접근을 적재·저장 명령어로 구분한다. 현대 CPU는 내부 구현이 다양하므로 분류만으로 성능을 판단하지 않는다.

C 소스

void inc(int *p)
{
    (*p)++;       /* 메모리에 있는 값을 1 늘린다 */
}

x86-64 (CISC)

inc:                        # x86-64 (CISC)
    inc  dword ptr [rdi]    # 메모리 읽기 + 1 + 메모리 쓰기를 명령어 하나로  (ff 07 · 2바이트)
    ret

RISC-V (RISC)

inc:                        # RV32IMC (RISC)
    lw   a1, 0(a0)          # ① 메모리 → 레지스터
    addi a1, a1, 1          # ② 레지스터에서 계산
    sw   a1, 0(a0)          # ③ 레지스터 → 메모리
    ret

예제 확인: Clang 17, -O2 · x86-64 및 RISC-V RV32IMC 목적 파일을 빌드하고 역어셈블한 결과 (표시된 명령어는 출력 형식을 정리)

CISCRISC

길이가변 (x86: 1~15바이트)기본 4바이트, C 확장 사용 시 2·4바이트 혼용

명령어 길이와 코드 크기

7장 · 9 / 10

명령어 개수와 기계어 코드의 바이트 수는 다르다. M 확장은 곱셈·나눗셈 연산을 하드웨어 명령어로 제공하고, C 확장은 자주 쓰는 명령어를 16비트로 인코딩한다. 8쪽의 inc() 한 함수를 네 가지 ISA로 컴파일하고, 오브젝트 파일의 .text 크기를 측정했다.

구성크기RV32I 대비차이가 나는 이유
RV32I16 B100%lw/addi/sw/ret, 각각 4바이트
RV32IM16 B100%이 함수에는 곱셈이 없어 M 추가 효과 없음
RV32IMC8 B50%네 명령어가 각각 16비트로 압축됨
x86-643 B참고용incl (%rdi) 2바이트 + ret 1바이트
SoC 연결이 예제에서는 C 확장 사용으로 코드가 16 B → 8 B가 되었지만, 작은 함수 하나의 결과를 전체 프로그램에 일반화하면 안 된다. RISC-V 명세는 C 확장이 전형적으로 약 25~30%의 코드 크기 감소를 제공한다고 설명한다. BRAM 크기·배치는 실제 Vivado 설정과 링커 스크립트로 확인한다.

MicroBlaze V의 선택 · 7장 정리

7장 · 10 / 10

MicroBlaze V는 설정 화면에서 파이프라인 구성을 고를 수 있다. 지원 ISA 구성과 별개로, 구현 최적화 옵션을 통해 파이프라인 단계를 선택할 수 있다. 단계 수는 면적·클록 주파수·명령어 처리 성능의 절충을 바꾼다. 5단 구성의 단계 이름은 IF · OF(명령어 해석·오퍼랜드 인출) · EX · MEM · WB다. 4단은 IF/OF/EX/WB, 3단은 Fetch/Decode/Execute, 8단은 IF/OF/EX/M0/M1/M2/M3/WB로 구분한다.

최적화 설정파이프라인우선하는 것
AREA (C_OPTIMIZATION=1)3단자원 사용 감소 — 일부 명령어는 여러 클록
THROUGHPUT (C_OPTIMIZATION=3)4단연산 처리량 우선
PERFORMANCE (C_OPTIMIZATION=0)5단처리 성능과 주파수의 균형
FREQUENCY (C_OPTIMIZATION=2)8단높은 주파수 목표, 실제 달성 여부는 구현·타이밍 확인

공식 근거: AMD UG1629 · Pipeline Architecture (2026.1) · UG1711 · Configuration Wizard

확인할 것AMD 문서에서 Microcontroller 프리셋은 AREA 최적화로 소개하지만, 현재 Vivado 프로젝트에서 실제 선택·저장된 구성은 확인되지 않았다. IP 설정의 Optimization과 C_OPTIMIZATION 값, 구현 후 Timing Report를 확인한다.
