명령어의 구조

32비트 명령어 한 개 안에는 '무엇을 할지'와 '무엇을 가지고 할지'가 정해진 자리에 들어 있다. RISC-V 명령어의 칸 나눔, 값과 주소를 가리키는 방법, 그리고 스택과 큐를 익힌다.

학습 목표 1명령어를 연산 코드와 오퍼랜드로 나눠 읽을 수 있다.
학습 목표 2즉시·레지스터·베이스+오프셋·PC 상대 주소지정을 구분할 수 있다.
학습 목표 3스택(LIFO)과 큐(FIFO)가 SoC 어디에 쓰이는지 안다.

연산 코드와 오퍼랜드

4장 · 2 / 10

명령어는 두 부분으로 이루어진다. 연산 코드(opcode)는 무엇을 할지(더하기, 읽기, 분기 …)를 정하고, 오퍼랜드(operand)는 그 일에 쓸 값이나 그 값이 있는 곳을 가리킨다. 어셈블리어로 쓰면 맨 앞 단어가 연산, 뒤에 쉼표로 나열한 것이 오퍼랜드다.

add   a0, a0, a1       # 연산: add    오퍼랜드: 목적지 a0, 원천 a0 · a1
addi  a0, a0, 5        # 연산: addi   오퍼랜드: 목적지 a0, 원천 a0 · 상수 5
lw    a5, 8(a4)        # 연산: lw     오퍼랜드: 목적지 a5, 주소 = a4 + 8
beq   a0, a1, label    # 연산: beq    오퍼랜드: 비교할 a0 · a1, 갈 곳 label
오퍼랜드 종류뜻예
레지스터CPU 안의 저장소 32개(x0~x31) 중 하나a0 = x10, sp = x2
즉시값(Immediate)명령어 안에 직접 적힌 상수5, 0x40000
메모리 주소레지스터 + 상수로 계산한 위치8(a4)
분기 목표지금 위치(PC)에서 떨어진 거리label → 분기 목표(예: PC에서 +8)
3-주소 형식RISC-V 연산 명령어는 목적지 1개 + 원천 2개를 따로 적는다: add rd, rs1, rs2
x0 = 0x0(zero)은 읽으면 항상 0이고, 쓰기는 무시된다. addi a0, zero, 5는 "a0에 5 넣기"가 된다.
레지스터 이름x10~x17은 함수 인자용 a0~a7, x1은 돌아갈 주소 ra. 자세한 표는 5장.

RISC-V 명령어 형식 — 32비트 칸 나눔

4장 · 3 / 10

RV32I의 기본 명령어는 32비트다. 공식 명세는 기본 4형식(R·I·S·U)과 즉시값 배치를 달리한 2개 변형(B·J)을 정의한다. 여섯 가지로 펼쳐 보면 아래와 같다. 32비트 명령어의 opcode는 비트 6~0이고, rd · rs1 · rs2가 존재할 때는 각각 정해진 위치를 사용한다. C 확장을 사용하면 별도로 16비트 압축 명령어도 실행한다.

명령어 해부 — 실제 비트 읽기

4장 · 4 / 10

명령어의 종류

4장 · 5 / 10

RISC-V 명령어는 하는 일에 따라 몇 묶음으로 나뉜다. 기본 정수 명령어 묶음(I)에 곱셈·나눗셈(M), 압축(C) 같은 선택 확장(extension)을 더할 수 있다. CSR 명령어는 별도 Zicsr 확장이고, mret은 머신 특권 모드 명령어다. MicroBlaze V는 지원하는 ISA 확장 중 실제 Vivado 설정에서 선택한 기능만 실행할 수 있다.

주소지정방식 ① 즉시 · 레지스터

4장 · 6 / 10

주소지정방식(addressing mode)은 오퍼랜드가 가리키는 값을 "어디서 가져오는가"의 규칙이다. 가장 단순한 두 가지는 값을 명령어 안에 직접 적는 즉시 방식과, 레지스터 번호만 적고 값은 레지스터에서 읽는 레지스터 방식이다.

한계addi 등 I형 산술은 부호 있는 12비트(−2048~2047). lui는 별도의 20비트 필드를 사용레지스터는 32개뿐
RISC-V 예addi andi ori sltiadd sub and or
핵심두 연산 방식 모두 피연산자를 얻기 위한 데이터 메모리 접근이 필요 없다. 다만 실제 실행 클록 수와 지연은 CPU 구현에 따라 다르다. RV32I의 일반 산술·논리 연산은 레지스터와 즉시값을 사용하고, 메모리 접근은 적재·저장 명령어로 분리된다.

주소지정방식 ② 베이스+오프셋 · PC 상대

4장 · 7 / 10

메모리에 있는 값이나 다른 명령어의 위치를 가리킬 때는 "기준 주소 + 거리"로 계산한다. 적재·저장은 레지스터를 기준으로 하는 베이스+오프셋 방식, 분기·점프는 지금 실행 중인 명령어 주소(PC)를 기준으로 하는 PC 상대 방식을 쓴다. 이렇게 계산된 최종 주소를 유효 주소(effective address)라 한다.

레지스터 간접레지스터에 든 값이 주소오프셋 0인 베이스+오프셋: lw a0, 0(a1)

SoC 연결주소맵이 "장치 베이스 주소 + 레지스터 오프셋"으로 구성되는 것은 이 방식과 잘 맞는다. 0x4002_0000은 교육용 배치 예시이므로 실제 Vivado Address Editor에서 베이스 주소를 확인해야 한다. lw/sw 오프셋(베이스)로 접근할 수 있는 범위는 명령어의 오프셋과 접근 정렬 제약을 따른다.

스택 — 나중에 넣은 것을 먼저 꺼낸다

4장 · 8 / 10

스택(stack)은 접시 쌓기처럼 마지막에 넣은 것을 먼저 꺼내는(LIFO, Last In First Out) 저장 구조다. CPU는 메모리 한쪽을 스택으로 쓰고, 꼭대기 위치를 스택 포인터 sp(x2)에 둔다. 함수에 들어간 뒤 필요하면 돌아갈 주소와 보존해야 할 레지스터 값을 스택에 저장하고, 복귀 전에 복원한다. RV32 표준 호출 규약에서는 스택이 낮은 주소로 자라며 sp를 16바이트 경계에 정렬해 유지한다.

실제로 컴파일된 함수의 스택 사용

f:                         # int f(int a, int b) { return sq(a) + sq(b); }
    addi sp, sp, -16       # 스택 16바이트 확보 (push 준비)
    sw   ra, 12(sp)        # 돌아갈 주소 저장
    sw   s0, 8(sp)         # 이 함수가 쓸 s0의 원래 값 저장
    sw   s1, 4(sp)         # s1의 원래 값 저장
    mv   s0, a1            # b를 s0에 보관 (sq 호출 중에도 유지)
    call sq                # t = sq(a)
    mv   s1, a0            # t를 s1에 보관
    mv   a0, s0
    call sq                # sq(b)
    add  a0, a0, s1        # 반환값 = sq(b) + t
    lw   ra, 12(sp)        # 저장했던 값 복원 (pop)
    lw   s0, 8(sp)
    lw   s1, 4(sp)
    addi sp, sp, 16        # 스택 되돌리기
    ret
핵심RV32I에는 일반적인 push·pop 전용 명령어가 없다. addi sp로 스택 프레임을 확보·해제하고 sw·lw로 저장·복원한다. 이 예제는 16바이트 단위로 스택을 확보해 ABI 정렬을 유지한다.

큐 — 먼저 넣은 것을 먼저 꺼낸다

4장 · 9 / 10

큐(queue)는 줄 서기처럼 먼저 들어온 것이 먼저 나가는(FIFO, First In First Out) 구조다. 보내는 쪽과 받는 쪽의 속도가 다를 때 사이에서 잠시 담아 두는 버퍼로 쓴다. 고정된 배열을 원처럼 돌려 쓰는 원형 큐(ring buffer)가 많이 사용한다.

원형 큐 (C)

#include <stdint.h>

#define QSIZE 8                     /* 칸 수 (2의 거듭제곱이면 나머지 계산이 쉽다) */

static uint8_t  q[QSIZE];           /* 데이터를 담는 칸 */
static uint32_t head = 0;           /* 다음에 꺼낼 칸 */
static uint32_t tail = 0;           /* 다음에 넣을 칸 */

/* 넣기: QSIZE 8칸 중 실제 저장 가능 7바이트. 성공 1, 가득 차면 0 */
int q_put(uint8_t v)
{
    uint32_t next = (tail + 1) % QSIZE;
    if (next == head)               /* 한 칸을 비워 두어 "가득"과 "비어 있음"을 구분 */
        return 0;
    q[tail] = v;
    tail = next;
    return 1;
}

/* 꺼내기: 비어 있으면 0, 성공하면 1 */
int q_get(uint8_t *v)
{
    if (head == tail)
        return 0;
    *v = q[head];
    head = (head + 1) % QSIZE;
    return 1;
}

SoC에서 보는 명령어 · 4장 정리

4장 · 10 / 10

UART 송신 함수를 RV32IMC 대상으로 컴파일하면 주소지정방식이 한눈에 보인다. lui(U 형식)로 장치 베이스를 만들고, lw·sw(베이스+오프셋)로 상태와 데이터를 다룬다. bnez는 bne를 쉽게 적은 의사 명령어다. 아래 베이스 주소는 예시이며, UART Lite의 상태 비트 3이 송신 FIFO 가득 참을 뜻한다.

C 소스

#include <stdint.h>

#define REG32(a)   (*(volatile uint32_t *)(a))
#define UART_BASE  0x40020000u      /* soc_map.h */
#define UART_TX    0x04u            /* 송신 FIFO */
#define UART_STAT  0x08u            /* 상태 레지스터 */

void uart_putc(char c)
{
    while (REG32(UART_BASE + UART_STAT) & 0x08u)   /* 송신 FIFO 가득 참 */
        ;
    REG32(UART_BASE + UART_TX) = (uint8_t)c;
}

RV32IMC 컴파일 결과 (Clang 17 · -O2, 핵심 명령어)

uart_putc:
    lui  a1, 262176         # 0x40020 → 베이스 0x4002_0000

    bnez a2, .LBB0_1        # 의사 명령어: bne a2, zero, .LBB0_1
    sw   a0, 4(a1)          # 0x4002_0004 : TX 데이터 쓰기
    ret                      # 함수 복귀
