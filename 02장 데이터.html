비트 · 바이트 · 워드

2장 · 2 / 10

디지털 회로는 정해진 전압 구간을 논리 0 또는 논리 1로 해석한다. 이 0/1 한 자리가 비트(bit)다. 비트 8개를 묶으면 바이트(byte), 32개를 묶으면 RISC-V에서 말하는 워드(word)가 된다. 여기서 사용하는 MicroBlaze V는 RV32 구성으로, 일반 목적 레지스터와 주소의 폭이 32비트다. 메모리는 바이트 단위로 주소를 부여하고, 워드 접근은 연속된 4바이트를 다룬다.

단위비트 수나타낼 수 있는 값의 개수RISC-V 명령어
비트12—
바이트8256lb · sb
하프워드1665,536lh · sh
워드32약 43억 (4,294,967,296)lw · sw
핵심n비트로는 2n가지 값을 나타낼 수 있다. 32비트 바이트 주소는 이론적으로 232바이트, 즉 4 GiB(약 4.29 GB)의 주소 공간을 표현한다. 실제 탑재된 RAM 용량과는 다르다.

2진수 — 자리마다 두 배

2장 · 3 / 10

10진수는 자리가 하나 올라갈 때마다 10배가 되고, 2진수는 2배가 된다. 맨 오른쪽 비트(비트 0)가 1, 그 왼쪽이 2, 4, 8 … 순이다. 1인 자리의 값을 모두 더하면 10진수가 된다.

10진수 → 2진수: 2로 계속 나누고 나머지를 거꾸로 읽기 (예: 13)
13 ÷ 26나머지 1
6 ÷ 23나머지 0
3 ÷ 21나머지 1
1 ÷ 20나머지 1
아래에서 위로 읽으면 1101 = 13
2진수10진수특징
0000_00011비트 0만 1
0000_10008비트 3만 1 = 23
1000_0000128비트 7만 1 = 27
1111_11112558비트 최댓값 = 28−1
SoC 연결스위치 SW3 하나만 올리면 GPIO가 읽는 값은 0000_1000 = 8이다. 스위치 번호가 곧 비트 번호다.

16진수 — 4비트를 한 글자로

2장 · 4 / 10

32비트를 2진수로 쓰면 32자리라 읽기 힘들다. 4비트(니블)는 0~15의 16가지 값이므로 16진수 한 글자(0~9, A~F)에 딱 맞는다. 그래서 32비트는 16진수 8자리로 쓴다. C 언어의 16진 정수는 0x40000000처럼 0x로 시작한다. 이 교재의 0x4000_0000에서 밑줄은 그림·주소표의 가독성용 표기이며, C 소스의 정수 리터럴에는 그대로 쓸 수 없다.

음수 — 2의 보수

2장 · 5 / 10

비트에는 빼기 기호가 없다. 컴퓨터는 2의 보수(Two's complement)로 음수를 나타낸다. 비트열을 부호 있는 2의 보수 정수로 해석할 때 최상위 비트가 1이면 음수다. 같은 비트열을 부호 없는 정수로 읽으면 값이 달라진다. 이 방식의 장점은 덧셈 회로 하나로 뺄셈까지 할 수 있다는 것이다: a − b = a + (−b).

C 자료형과 범위

2장 · 6 / 10

C 프로그램에서 변수의 자료형은 "몇 비트를, 부호 있게 읽을지"를 정한다. 임베디드 코드에서는 크기가 분명한 stdint.h의 자료형을 쓴다. 부호 없는 정수로의 변환은 비트 폭에 따른 나머지 연산처럼 동작한다. 반면, 부호 있는 정수의 범위 초과·변환은 같은 결과를 보장하지 않으므로 구분해야 한다.

자료형비트범위SoC 코드에서 쓰임
uint8_t80 ~ 255UART로 주고받는 1바이트
int8_t8−128 ~ 127—
uint16_t160 ~ 65,535스위치 16개 값, SEG7 표시값
int16_t16−32,768 ~ 32,767온도 센서 원시값(음수 온도)
uint32_t320 ~ 4,294,967,295레지스터 · 주소 · 타이머 카운트
int32_t32약 ±21억일반 계산
#include <stdint.h>

uint8_t a = 255;
a = a + 1;           /* 8비트 부호 없는 형에 저장 → 0 */

int8_t b = 127;
int16_t next = b + 1; /* 128: int8_t 범위 밖 */
RV32 기준일반적인 MicroBlaze V RV32 툴체인에서 int와 포인터는 32비트다. int8_t에 128을 다시 대입하는 결과는 C 구현에 따라 달라질 수 있다. RV32IMC처럼 FPU가 없는 설정의 float 연산은 소프트웨어에 의존한다.

비트 연산과 마스크

2장 · 7 / 10

레지스터는 32비트 한 덩어리지만, 실제로는 비트 하나하나가 LED 하나, 스위치 하나, 설정 하나를 뜻한다. 그래서 다른 비트는 건드리지 않고 원하는 비트만 바꾸는 비트 연산을 쓴다. 바꿀 위치만 1로 만든 값을 마스크(mask)라 한다.

연산C예 (8비트)쓰는 곳
ANDa & b1010_1100 & 0000_1111 = 0000_1100특정 비트만 남기기(읽기)
ORa | b1010_0000 | 0000_1000 = 1010_1000특정 비트 켜기
XORa ^ b1010_1000 ^ 0000_1000 = 1010_0000특정 비트 뒤집기
NOT~a~0000_1000 = 1111_0111비트 반전(8비트로 표시한 예)
시프트a << n, a >> n1 << 3 = 0000_1000n번 비트 마스크 만들기
표기표의 밑줄 친 0·1은 8비트 계산 예시이며 C 정수 리터럴이 아니다. C 코드에서는 0xA0처럼 16진수를 사용한다. ~는 정수 승격과 형의 비트 폭에 주의한다.
#include <stdint.h>

uint32_t led = 0xA0;          /* 1010_0000 */
led |=  (1u << 3);            /* LED3 켜기   → 1010_1000 */
led &= ~(1u << 7);            /* LED7 끄기   → 0010_1000 */
led ^=  (1u << 5);            /* LED5 뒤집기 → 0000_1000 */
uint32_t sw = 0x10;            /* SW4만 켜진 GPIO 입력값 예시 */
int sw4 = (sw >> 4) & 1u;     /* 스위치 SW4 값은 1 */

문자 — ASCII 코드

2장 · 8 / 10

글자도 숫자로 저장된다. 영문자·숫자·기호에 0~127 번호를 붙인 표가 ASCII다. 키보드로 친 A는 UART를 통해 숫자 0x41 하나로 전달되고, 프로그램은 프로그램은 이 바이트 값들을 해석해 명령을 알아낸다.

/* 16진수 글자 하나 → 값 (0~15) */
int hex_val(char c) {
  if (c >= '0' && c <= '9') return c - '0';
  if (c >= 'A' && c <= 'F') return c - 'A' + 10;
  if (c >= 'a' && c <= 'f') return c - 'a' + 10;
  return -1;   /* 16진수 글자가 아님 */
}
한글ASCII에는 한글이 없다. UTF-8에서 한글 완성형 음절은 보통 3바이트다(예: '가' → EA B0 80). 조합 자모 등은 바이트 수가 달라질 수 있다. 실습 콘솔은 영문 명령만 쓴다.
SoC 연결UART 콘솔에서 disp 1234의 숫자 문자열을 10진수로 해석하면 값은 1234(0x04D2)다. 16진수로 해석하도록 작성한 파서라면 0x1234가 된다. 명령 파서의 진법 규칙을 먼저 정해야 한다.

엔디안 — 바이트를 놓는 순서

2장 · 9 / 10

메모리는 주소 하나에 1바이트씩 저장한다. 4바이트짜리 워드를 저장하려면 주소 4개를 쓰는데, 어느 바이트를 낮은 주소에 놓을지 두 가지 약속이 있다. 낮은 주소에 낮은 자리 바이트를 놓으면 리틀 엔디안(Little-endian), 높은 자리 바이트를 놓으면 빅 엔디안(Big-endian)이다.

리틀 엔디안빅 엔디안

예MicroBlaze V, x86, 일반적인 ARM 설정일부 아키텍처 설정, 네트워크 바이트 순서
문제가 되는 때워드를 바이트 단위로 쪼개 보낼 때, 메모리 덤프를 읽을 때
핵심32비트 값을 동일한 시스템에서 워드 단위로 읽고 쓰는 동안에는 보통 엔디안 차이가 드러나지 않는다. 메모리 덤프·바이트 배열·파일·통신 프로토콜처럼 바이트 경계를 넘나들면 저장·전송 순서를 확인해야 한다.
